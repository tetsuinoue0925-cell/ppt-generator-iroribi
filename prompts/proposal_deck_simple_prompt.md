# 提案資料 構成 JSON 生成プロンプト（設計JSON方言 / シンプル3型）

クライアント向け提案資料の構成を、**設計JSON方言**（`meta` + `slides[].layout`、layout 3型）で出力させるための雛形。
リッチデッキ13型（`presentation` + `slides[].type`）版は `prompts/proposal_deck_prompt.md` を参照。

出力された JSON は `input/slides.json` に保存し、`node src/generate.js input/slides.json output/提案.pptx` で .pptx 化する。

---

## 貼り付け用プロンプト

```
あなたはコンサルティング提案資料の構成を設計する担当です。
以下の内容・添付資料をもとに、指定スキーマに厳密に従う JSON だけを出力してください。
説明文・前置き・コードフェンス（```）は一切付けず、JSON本体のみを返してください。

# ルール
- 装飾（色・フォント・座標）は出力しない。内容と強調点だけを構造化する。
- 各スライドは layout / title / message / elements / speaker_notes を持つ。
- layout は次の3型のみ（新しい型を勝手に作らない）:
  - title:    表紙・章扉。elements.subtitle（任意）でサブタイトルを補足。
  - message:  1メッセージ + 補足箇条書き。message に主張を1文で、elements.bullets に補足を3点程度（文字列配列）。
  - cards_3:  3項目の比較・並列。elements.cards に {title, body} を最大3つ。
- どの型にも当てはまらない内容は、最も近い型に寄せる。
- タイトル・主張・補足はすべて体言止め（ですます調禁止）。
- 強調表現は本文中の <strong>テキスト</strong> のみ（他のHTMLタグ不可）。

# スライド構成（全体で約30枚に収める）
下表を骨格にする。内容量に応じて1項目を2枚に分割してよい。逆に薄い項目は前後と統合してよい。

| #  | 項目                     | 推奨 layout | 補足                                      |
|----|--------------------------|-------------|-------------------------------------------|
| 表紙 | -                      | title       | title=資料タイトル, elements.subtitle=サブタイトル |
| 1  | エグゼクティブサマリ     | message     | message=結論1文, bullets=根拠3〜4点       |
| 2  | 背景・課題認識           | message     | message=課題の核心, bullets=外部環境・内部事情 |
| 3  | 現状（As-Is）            | cards_3     | cards=現状の主要課題を3点で並列           |
| 4  | あるべき姿（To-Be）      | cards_3     | cards=解決後の状態を3点で並列            |
| 5  | ギャップ分析             | message     | message=ギャップの本質, bullets=観点ごとのギャップ |
| 6  | 解決アプローチ           | cards_3     | cards=打ち手3つ（各タイトル＋概要）       |
| 7  | 期待効果                 | message     | message=主要効果1文, bullets=定量・定性効果 |
| 8  | プロジェクト体制         | message     | message=体制方針, bullets=役割・責任範囲  |
| 9  | スケジュール概要         | cards_3     | cards=フェーズ3つ（時期・内容・成果物）   |
| 10 | 概算費用・前提条件       | message     | message=総費用感, bullets=費用内訳・前提条件 |
| 11 | 次のステップ・依頼事項   | cards_3     | cards=アクション3点（担当・期限・内容）   |
| 章扉 | 任意                   | title       | 大きな塊の前に「現状分析」「実行計画」等  |

# speaker_notes（発表者ノート）必須
各スライドのトップレベルに "speaker_notes": "..." を必ず付与する（content の中ではない）。
- 文字数: 200~400字（1~2分で話せる量）
- そのスライドで口頭で補足する内容を具体的に記述
- ですます調で記述（スライド本文は体言止め、ノートだけ丁寧体）
- スライドに載せていない補足情報・数値の根拠・背景も1点含める

## 使い方

1. 上記プロンプトの末尾に提案内容・添付資料を貼って Gemini/Claude に渡す。
2. 返ってきた JSON を `input/slides.json`（または `cases/<案件名>/slides.json`）に保存。
3. 生成:
   ```
   node src/generate.js input/slides.json output/提案.pptx
   # または
   docker compose run --rm generate node src/generate.js input/slides.json output/提案.pptx
   ```
4. PowerPoint で人間が最終調整（図表の差し込み・文言確認）。

## リッチデッキ版との使い分け

| 観点 | このプロンプト（設計JSON / 3型） | `proposal_deck_prompt.md`（リッチデッキ / 13型） |
|------|-------------------------------|------------------------------------------------|
| スライド型数 | 3型（シンプル） | 13型（表・タイムライン・数値強調 等） |
| speaker_notes | 100〜200字（簡潔） | 300〜600字（詳細・想定Q&A付き） |
| 向いている場面 | 初稿・素早いたたき台・社内共有 | クライアント最終提出・重要プレゼン |
| スキーマ検証 | `npm run validate` 対応 | `generate.js` 内蔵 validateDeck のみ |
