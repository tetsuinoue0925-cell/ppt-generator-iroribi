# 製造業SaaS×AI×DX 提案資料 JSON 生成プロンプト（リッチデッキ方言 / Iroribi テーマ）

「省エネ+α でつくるスマート工場」型の製造業向け SaaS×AI×DX 導入提案資料の構成を、Gemini Canvas や Claude に**リッチデッキ方言**（`presentation` + `slides[].type`、Iroribi テーマ）で出力させるための雛形。
出力された JSON は `cases/<案件名>/deck.json` に保存し、`node src/generate.js cases/<案件名>/deck.json cases/<案件名>/提案.pptx` で .pptx 化する。

汎用のクライアント提案資料向け雛形は `prompts/proposal_deck_prompt.md`、設計JSON（3型）向けは `prompts/proposal_deck_simple_prompt.md` を参照。

---

## 貼り付け用プロンプト

```
あなたは製造業向け SaaS×AI×DX 導入提案資料（省エネ・予知保全・DX）の構成を設計する担当です。
以下のクライアント情報・提案概要をもとに、指定スキーマに厳密に従う JSON だけを出力してください。
説明文・前置き・コードフェンス（```）は一切付けず、JSON本体のみを返してください。

# 出力形式（重要）
- 出力は JSON の「配列」ではなく、次の形の単一オブジェクトです:
  { "presentation": { "title": "...", "theme": "iroribi" }, "slides": [ {...}, {...} ] }
- 裏表紙（ロゴのみのclosingスライド）は生成エンジン側が自動付加するため、JSONには含めないでください。
- 値に色・フォント・座標・pt指定は一切含めないでください（テンプレート側のIroribiテーマで固定されるため）。
- 強調表現は本文中の <strong>テキスト</strong> のみ使用可（他のHTMLタグは使わない）。

## 2. 1スライド1メッセージ徹底
1枚で伝えることは1つだけ。情報量が多い場合（特に ギャップ分析・期待効果）は複数枚に分割する。

## 3. 3要素構成（タイトル／リード文／ボディ）
各スライドは次の3層で構成する。

- **タイトル**（= `header.h2`）: テーマ・問いを簡潔に。タイトルだけで内容が完全にわかること。句読点不要。
- **リード文**: 結論を全角30字以内・最大2行で言い切る。句読点不要。配置先は type ごとの「リード用スロット」を使う:
  - bullet-list / table / two-column-mixed / two-column-tiled / tiled-content → `content.pre_text`
  - highlight-numbers → `content.footer`（数値群の下に結論として）
  - qa-layout → `content.description`
  - timeline / section-title → リード相当は `header.tag`（短い英字カテゴリラベル）で代替してよい
- **ボディ**: リード文を補強する根拠・事実のみ。type ごとの本文スロット（`content.items` / `content.rows` / `content.tiles` 等）に入れる。
  - **`bullet-list` の `content.items`** — 各要素は**必ずオブジェクト**で記述する（平文字列を渡すと本文が空白になる）。
    - `strong`: メイン行（太字・大きめ）。箇条書き本体。
    - `subtext`: 補足行（細字・小さめ）。数値・出典・補足がある場合のみ。省略可。
    ```json
    { "strong": "電力高騰とCO2規制対応が急務", "subtext": "2030年カーボンニュートラル目標・省エネ法改正でエネルギー管理の高度化が不可避" }
    ```
  - **`table` の `content.rows`** — **配列の配列**形式で記述する。先頭行がヘッダ行として自動認識される。
    ```json
    "rows": [
      ["観点", "As-Is 現状", "To-Be あるべき姿", "ギャップ"],
      ["エネルギー把握", "工場全体の月次電力量のみ", "設備単位のリアルタイム消費可視化", "計測基盤・分析ツールの未整備"]
    ]
    ```
  - **`tiled-content` / `two-column-tiled` の `content.tiles`**: `{ "title": "タイル見出し", "body": "本文（改行は\\n）" }` 形式（`body` は平文で可）。
  - **`timeline` の `content.items`**: `{ "phase": "時期", "title": "マイルストーン", "description": "詳細" }` 形式（3フィールド必須）。
  - **`highlight-numbers` の `content.numbers`**: `{ "value": "▲80%", "label": "突発故障削減" }` 形式。削減は `▲XX%`、向上は `+XXpt` を value に入れる。

## 4. 体言止め・名詞止め徹底
タイトル・リード文・ボディはすべて体言止め（ですます調禁止）。
※ ただし speaker_notes（発表者ノート）だけは例外でですます調にする。

## 5. 製造業用語の使い方
OEE（設備総合効率）/ FEMS（工場エネルギー管理システム）/ PdM（予知保全）/ TBM（時間基準保全）/ CBM（状態基準保全）/ デマンドコントロール は使ってよい。
各用語は**初出時のみ**カッコで正式名称を補足し、2回目以降は略称のみで構わない。

## 5-2. ベンチマーク・競合参考情報（speaker_notes の根拠として使う）
以下の市場知識を speaker_notes に反映してよい（スライド本文には載せず、口頭補足として活用）。

**省エネ/FEMS系プレイヤー**
- 国内: 富士電機FEMS（製造業実績豊富・設備連携強いがカスタマイズ工期長）、アズビルEcoPlus（ビルBA強みだが工場ラインには不向き）、東芝Eco Optimization（大手向けで中小SMBへの対応薄い）
- 海外: Schneider Electric EcoStruxure（グローバル標準・センサー縛りあり）、Siemens EnergyManager（Siemens設備前提・他社設備連携弱い）

**予知保全/PdM系プレイヤー**
- 国内: 日立Lumada（エンタープライズ向け・導入コスト大）、NEC先進AIプラットフォーム（個社実装だがSaaS化進んでいない）
- 海外: C3.ai（大手向け・年数億円規模の投資前提）、Uptake（米国製造業特化・日本語未対応）、GE Predix（GE設備前提）、SKF Enlight（軸受特化で汎用性低い）

**工場IoTプラットフォーム**
- 国内: FANUC Field System（FANUC機器前提）、三菱電機e-F@ctory（三菱PLC前提・他社設備連携制限あり）
- 海外: PTC ThingWorx（高機能だが実装コスト高・IT人材必要）、AWS IoT SiteWise（インフラ層のみ・上位分析は別途構築必要）

**Iroribiが勝てる軸（共通）**: 複数カテゴリを1基盤で提供・個社AI（汎用閾値でない）・SMB対応・最短2週間稼働・センサー非依存

## 6. 図が必要な場合
- スライドの主役が図そのものの場合: `type: "bleed-image"` を使い、`image_alt` に「〇〇図：何を示すか・データソース」を記述する（実画像は取得しないプレースホルダ枠になる）。
- 箇条書きの一項目として図が必要な場合: その項目のテキストに「【図】〇〇図：何を示すか」と記述する（人間がPowerPoint側で後から差し込む前提の空白マーカー）。

## 7. フォントサイズ・色・座標について
これらはすべてIroribiテンプレート側（テーマ・レイアウトコード）で固定されています。JSON側で指定・言及しないでください。

## 8. speaker_notes（発表者ノート）必須
各スライドのトップレベルに `"speaker_notes": "..."` を必ず付与する（`content` の中ではない）。
- 文字数: 300〜600字（1〜2分で話せる量）
- そのスライドで口頭で話す内容を具体的に記述（製造現場の担当者・経営層への語りかけ文体）
- スライドに載せていない補足情報・数値の根拠・業界事例も含める
- 想定される質問とその回答を1〜2つ入れる（特に「導入コスト」「既存設備への影響」「セキュリティ」に関する質問を想定）
- ですます調で記述（スライド本文とは対照的に、ここだけ丁寧体）

## 9. 出力形式（再掲）
- JSON単一オブジェクトのみ。前後の説明文・コードフェンス不要。
- 全スライドに `header`（h2/必要ならtag）・`content`・`speaker_notes` を必須で含める。

## 使い方

1. 上記プロンプトの「変換対象」欄にクライアント固有の情報（ヒアリングメモ・既存提案書の内容など）を貼って Gemini/Claude に渡す。
2. 返ってきた JSON を `cases/<案件名>/deck.json` に保存。
3. 生成:
   ```
   node src/generate.js cases/<案件名>/deck.json cases/<案件名>/提案.pptx
   # または
   docker compose run --rm generate node src/generate.js cases/<案件名>/deck.json cases/<案件名>/提案.pptx
   ```
4. PowerPoint で人間が最終調整（効果試算の数値確認・図表の差し込み・費用欄の更新）。

`node src/validate.js` は設計JSON方言（slides.schema.json）専用のため、リッチデッキ方言のJSONには使えない。スキーマ検証は `generate.js` 実行時に内蔵の `validateDeck` が自動で行う（不正があれば生成前にエラー終了する）。
