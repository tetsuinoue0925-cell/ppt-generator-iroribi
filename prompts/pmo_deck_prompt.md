# PMO資料 構成 JSON 生成プロンプト（リッチデッキ方言 / Iroribi テーマ）

受注後のプロジェクト内打合せ資料（PMO資料・定例会議資料）の構成案を、Gemini Canvas や Claude に**リッチデッキ方言**（`presentation` + `slides[].type`、Iroribi テーマ）で出力させるための雛形。
出力された JSON は `cases/<案件名>/pmo_deck.json` に保存し、`node src/generate.js cases/<案件名>/pmo_deck.json cases/<案件名>/PMO資料.pptx` で .pptx 化する。

クライアント向け提案資料の雛形は `prompts/proposal_deck_prompt.md`、簡易方言向けの雛形は `prompts/json_design_prompt.md` を参照。

---

## 貼り付け用プロンプト

```
あなたはプロジェクト内定例会議資料（PMO資料）の構成を設計する担当です。
以下の内容・添付資料をもとに、指定スキーマに厳密に従う JSON だけを出力してください。
説明文・前置き・コードフェンス（```）は一切付けず、JSON本体のみを返してください。

# 出力形式（重要）
- 出力は JSON の「配列」ではなく、次の形の単一オブジェクトです:
  { "presentation": { "title": "...", "theme": "iroribi" }, "slides": [ {...}, {...} ] }
- 裏表紙（ロゴのみのclosingスライド）は生成エンジン側が自動付加するため、JSONには含めないでください。
- 値に色・フォント・座標・pt指定は一切含めないでください（テンプレート側のIroribiテーマで固定されるため）。
- 強調表現は本文中の <strong>テキスト</strong> のみ使用可（他のHTMLタグは使わない）。

# スライド構成ルール

## 1. 標準アジェンダ（全体で10〜15枚程度を目安に収める。論点量に応じて増減可）
プロジェクト内打合せ資料（PMO資料）として、以下8項目を骨格にする（内容量に応じて1項目を2枚に分割してよい。逆に薄い項目は前後と統合してよい）。
各項目の内容に最も適した type を選ぶ。

| # | 項目 | 推奨 type | 補足 |
|---|------|-----------|------|
| 表紙 | - | title-slide | content.h1=資料タイトル, content.subtitle=会議名・開催日など |
| 1 | アジェンダ・本日のゴール | bullet-list | content.pre_text=本日のゴール, content.items=本日の議題一覧 |
| 2 | 前回からの進捗サマリ | highlight-numbers | 進捗率・完了タスク数等を数値で。詳細は別途tableで補足してもよい |
| 3 | 調査・分析結果の報告 | table または bleed-image | 列例: 観点／結果／示唆。図がメインの場合は bleed-image + image_alt |
| 4 | スケジュール（計画 vs 実績） | table | 列例: フェーズ／計画／実績／進捗状況 |
| 5 | 役割・体制の再確認 | table | 列例: 役割／担当／責任範囲（RACI） |
| 6 | 課題・リスク・論点 | table | 列例: 項目／内容／対応方針／区分（課題・リスク・論点） |
| 7 | 意思決定依頼事項 | qa-layout | content.items=クライアントへの依頼事項の配列 |
| 8 | 次のToDo（担当・期限） | table | 列例: ToDo／担当／期限 |
| 章扉（任意） | - | section-title | 論点が多く前半/後半などに分けたい場合のみ挿入 |

実際に使う type は上表を出発点としつつ、内容に最も近いものを選ぶこと（無理に当てはめない）。

## 2. 1スライド1メッセージ徹底
1枚で伝えることは1つだけ。情報量が多い項目（特に課題・リスク・論点や調査結果）は複数枚に分割する。

## 3. 3要素構成（タイトル／リード文／ボディ）
各スライドは次の3層で構成する。

- **タイトル**（= `header.h2`）: テーマ・問いを簡潔に。タイトルだけで内容が完全にわかること。句読点不要。
- **リード文**: 結論を全角30字以内・最大2行で言い切る。句読点不要。配置先は type ごとの「リード用スロット」を使う:
  - bullet-list / table / two-column-mixed / two-column-tiled / tiled-content → `content.pre_text`
  - highlight-numbers → `content.footer`（数値群の下に結論として）
  - qa-layout → `content.description`
  - timeline / section-title → リード相当は `header.tag`（短い英字カテゴリラベル）で代替してよい
- **ボディ**: リード文を補強する根拠・事実のみ。type ごとの本文スロット（`content.items` / `content.rows` / `content.tiles` 等）に入れる。
  - **`bullet-list` の `content.items`** — 各要素は**必ずオブジェクト**で記述する（平文字列を渡すと本文が空白になる）。
    - `strong`: メイン行（太字・大きめ）。箇条書き本体。
    - `subtext`: 補足行（細字・小さめ）。担当者・期限・補足がある場合のみ。省略可。
    ```json
    { "strong": "キックオフ会議の開催日程を確定", "subtext": "担当: 井上 / 期限: 5月18日" }
    ```
  - **`table` の `content.rows`** — **配列の配列**形式で記述する。先頭行がヘッダ行として自動認識される。
    ```json
    "rows": [
      ["フェーズ", "計画", "実績", "進捗状況"],
      ["データ取得", "6月末", "6月末", "完了"],
      ["分析", "7月前半", "7月後半", "遅延中"]
    ]
    ```
    ※ `{ "cells": [...] }` オブジェクト形式も可だが、配列形式の方がシンプルで推奨。
  - **`highlight-numbers` の `content.numbers`**: `{ "value": "80%", "label": "タスク完了率" }` 形式。
  - **`timeline` の `content.items`**: `{ "phase": "時期", "title": "マイルストーン", "description": "詳細" }` 形式。

## 4. 体言止め・名詞止め徹底
タイトル・リード文・ボディはすべて体言止め（ですます調禁止）。
※ ただし note 7 の speaker_notes（発表者ノート）だけは例外でですます調にする。

## 5. 図が必要な場合
- スライドの主役が図そのものの場合（特に「調査・分析結果の報告」）: `type: "bleed-image"` を使い、`image_alt` に「〇〇図：何を示すか・データソース」を記述する（実画像は取得しないプレースホルダ枠になる）。
- 箇条書きの一項目として図が必要な場合: その項目のテキストに「【図】〇〇図：何を示すか・データソース」と記述する（人間がPowerPoint側で後から差し込む前提の空白マーカー）。

## 6. フォントサイズ・色・座標について
これらはすべてIroribiテンプレート側（テーマ・レイアウトコード）で固定されています。JSON側で指定・言及しないでください。

## 7. speaker_notes（発表者ノート）必須
各スライドのトップレベルに `"speaker_notes": "..."` を必ず付与する（`content` の中ではない）。
- 文字数: 300〜600字（1〜2分で話せる量）
- 進行役（PM）がそのスライドで口頭で話す内容を具体的に記述（聴衆=プロジェクト関係者・クライアントへの語りかけ文体）
- スライドに載せていない補足情報・数値の根拠・背景も含める
- 想定される質問とその回答を1〜2つ入れる（特に課題・リスク・スケジュール遅延に関する質問を想定）
- ですます調で記述（スライド本文とは対照的に、ここだけ丁寧体）

## 8. 出力形式（再掲）
- JSON単一オブジェクトのみ。前後の説明文・コードフェンス不要。
- 全スライドに `header`（h2/必要ならtag）・`content`・`speaker_notes` を必須で含める。

## 使い方

1. 上記プロンプトの末尾に、今回の定例会議で報告する内容・添付資料を貼って Gemini/Claude に渡す。
2. 返ってきた JSON を `cases/<案件名>/pmo_deck.json` に保存。
3. `node src/generate.js cases/<案件名>/pmo_deck.json cases/<案件名>/PMO資料.pptx` で生成（`docker compose run --rm generate node src/generate.js ...` でも可）。
4. PowerPoint で人間が最終調整（図表の差し込み・最新数値の確認）。

`node src/validate.js` は簡易方言（slides.schema.json）専用のため、リッチデッキ方言のJSONには使えない。スキーマ検証は `generate.js` 実行時に内蔵の `validateDeck` が自動で行う（不正があれば生成前にエラー終了する）。
